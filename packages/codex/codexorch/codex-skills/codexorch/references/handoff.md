# Handoff

Use for a requested transferable checkpoint. Inspect current branch, changed paths, recent relevant commits and actual checks. Report goal status, ownership, changed artifacts, accepted decisions, command/exit evidence, blockers and next dependency-ready action. Distinguish pending from completed; do not commit, publish, clear a session or write durable memory as a side effect.

For product implementation dispatch, carry the verified project contract and executor's required Jira/Figma MCP tools explicitly. A tool-enabled Codex context worker collects the ticket, parent and all linked/referenced issues with complete comments/changelog, every linked structured Figma node (design and text-and-labels), text-source ranges and analogous target screen/ViewModel/usecase/API behavior before implementation dispatch. Name consumed source revisions, comment dates/IDs, node IDs and ranges, not merely links or registered servers; the generic scout does not supply this evidence.

Keep required facts and a compact AC matrix inline; pin bulky evidence separately by revision. Each row carries AC/linked-comment clarification, business behavior/override, target, implementation path and evidence/result. Include affected variants and loading/empty/error/success/navigation states ONLY when the ticket or linked comments request them. Preserve unrelated flows and identify conflicting or unavailable required sources as unresolved dependent acceptance, not guessed completion.

Handoff to an independent reviewer at the candidate commit, or base SHA plus frozen working-tree change set for no-commit projects. Include the tracked diff vs base, staged changes, and untracked files with contents; nobody edits the candidate during review. Review every AC row and required Figma property, verify locale keys and planned/actual counts against app authority, and inspect the diff for no changed product tests. Report existing-check commands/exits plus required business-state, visual/property and locale/diff evidence: existing-tests-only never excuses missing acceptance evidence. Blocking findings are unmet ticket requirements or regressions caused by the candidate; unrelated pre-existing defects are P3/non-blocking. Confirm no push; return "not pushed", "not committed" for no-commit packs, branch/candidate identity and per-row pass/fail/unresolved gaps for the owner's next action.

Provenance: `pre-release-2.108.13:commands/handoff.md` and `references/handoff.md` (MIT). This replaces the command trigger with a conditional skill reference; no legacy runtime dependency.
